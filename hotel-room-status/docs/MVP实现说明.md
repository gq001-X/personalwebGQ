# 酒店房态协同 MVP 实现说明

## 与原技术方案的关系

原有《技术方案》保留调研依据和完整目标。本次根据课堂 MVP 要求交付可运行的最小闭环：前台核对房态、检索规则和生成解释，人工分派，客房人员确认接手。六位访谈对象在最小演示中归并为管理员、前台、客房三个操作角色；这不是对真实酒店岗位授权的替代。

## 架构与数据

浏览器 → FastAPI认证与租户范围 → 固定Harness → SQLite快照/知识/图谱 → Ollama解释 → 输出检查 → 人工交接 → 审计。

Python 3.12、FastAPI、Pydantic、标准库 SQLite、PyYAML、Uvicorn；httpx仅用于验证。没有引入Redis、向量数据库、Neo4j或额外智能体框架。前端通过FastAPI同源提供，公网HTTPS由独立Tunnel接入。Ollama接口仍仅在本机访问。

数据库包含 tenants、users、sessions、attempts、cases、knowledge、wiki、edges、runs、handoffs、audits、usage。业务查询在SQL中限定租户。模型请求之前完成授权；不会先读取其他酒店资料再交给模型过滤。运行结果保存当时证据全文与版本，便于复核。当前知识表保存最新内容，完整文档历史回滚尚未实现。

种子资料来自 discovery-report.md 的 f10/f31/f50（清扫与查房差异）、f11/f44（维修复查）、f23/f25（交接）、f34/f35（时间与故障）。每家店5个合成房态与4条规则，样本不是实时PMS数据。12小时过期阈值是课堂实现参数，生产使用前需业务确认。

## Harness 与知识处理

Harness 为固定Python执行流程，模型不具有任意工具选择或代码执行权。已认证请求依次执行业务范围、预期版本、关键词和图谱检索、确定性规则、受限模型解释、结构与引用检查、再次校验版本、保存运行轨迹。可用信息工具仅为读取业务快照、检索本店知识、读取关系图谱。

RAG 先按租户筛选文章，再按中文双字词项和英文词项匹配，并加入业务图谱直接关系，最多4条。没有匹配时返回缺依据，不调用模型。它适合本次小样本，不具有向量检索的同义词召回能力，也未做大规模知识效果评测。

LLM Wiki 以某一版本的原文为输入调用 Ollama，产生DRAFT；管理员阅读后发布为PUBLISHED，并加入“引用来源”图谱关系。普通用户只看到已发布页面。原文变化会阻止旧草稿发布，已发布页面显示来源版本差异。Wiki页独立展示，RAG当前检索的是原始知识表。

模型JSON结构由Pydantic验证，引用ID必须来自本次证据；危险字面承诺触发规则降级。两条明确否定系统放行能力的完整规则原句可通过保守检查。此检查存在措辞局限，不等同于语义正确性证明，最终交付由人工负责。

## 权限矩阵

| 操作 | 管理员 | 前台 | 客房 |
| --- | --- | --- | --- |
| 本店房态、问答、已发布Wiki、图谱 | 允许 | 允许 | 允许 |
| 发起交接 | 允许 | 允许 | 禁止 |
| 确认接手 | 仅本人被指定时 | 仅本人被指定时 | 仅本人被指定时 |
| 账号管理、知识维护、演示快照编辑、审计 | 允许 | 禁止 | 禁止 |
| Wiki生成、审核发布 | 允许 | 禁止 | 禁止 |
| 跨租户访问 | 禁止 | 禁止 | 禁止 |

当前分派接手人仅可选择本店有效客房用户，因此实际接手由指定客房账号完成。权限来自会话关联的数据库用户，不能通过请求自报role或tenant。管理员仅管理本租户，不设可随意跨店的超级管理员。套餐配额按调用尝试次数原子扣减，基础版20次/日、教学版200次/日，没有支付模块。

## 人工确认和错误处理

交接需confirmed=true且接手人为本店有效客房账号。分派不等于接手，接手不等于查房合格。run_id唯一避免重复建单；接手接口重复调用保留原确认时间。提交和接手均检查版本，发生冲突返回409并保留原记录。

接口成功返回ok=true、data业务数据、error空字符串字段；失败返回ok=false、data=null、error.code和error.msg。认证401、权限403、不可见对象404、版本409、参数422、配额429、模型无法编译Wiki503。HTML页面和静态资源按对应媒体类型返回。

口令加盐哈希、令牌摘要、输入大小限制、登录失败限流、CSP、同源文本渲染共同约束课堂公网演示。未实现多因素登录、企业SSO、备份恢复自动化、分布式限流或生产高可用。审计为本地可查询记录，不宣称具备防篡改存储。

## 阶段交付与风险

变更文件为app、static、tests、scripts、run.py、config.yaml、requirements.txt、requirements-lock.txt、README及本次新增文档。启动命令、可跑验证脚本、测试结果见README和MVP验收记录。

最可能出现的是本地模型冷启动超时、模型措辞被保守校验拒绝，以及电脑休眠造成公网网址失效。规则模式明确展示降级；Wiki生成失败需重试；隧道重启需重新发送网址。没有测量真实入住等待下降或ROI，也未进行真实酒店试点验收。

## 免登录访客补充

为方便老师通过表格中的网址直接查看，首页默认进入只读访客演示。新增app/demo.py与GET /api/demo，仅提供代码中固定的公开合成样例，不读取任何租户数据库或管理员新增资料；访客不创建会话、不调用模型、不写入任务。公开规则核对明确显示“未调用模型”。工作人员点击右上角登录后，仍使用原有租户隔离、角色权限与人工确认机制。

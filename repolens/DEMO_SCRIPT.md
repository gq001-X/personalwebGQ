# RepoLens · 五分钟展示讲稿

## 开始前

- 打开 http://127.0.0.1:8501；如果未运行，双击 start.cmd。
- 浏览器缩放保持 100%，建议全屏。
- 演示使用内置订单项目，不依赖网络和 API Key。
- CLI 预生成的报告在 reports 目录，可在网页暂时不可用时打开 Markdown 备用。

## 0:00–0:35｜项目目标

“我的项目叫 RepoLens，代码洞察智能体。它面向接手陌生代码仓库的场景，把目录探索、代码阅读、调用分析和问题审查串起来。最终交付一份能够追溯到代码位置的报告。”

说明首版对象是 Python 仓库。页面侧栏清楚显示本地分析和模型配置状态。

## 0:35–1:15｜现场扫描

点击“一键演示 · 扫描示例项目”。

“这里不是预置的结果页面。工具正在读取示例仓库，建立语法树、提取符号、解析调用，再运行规则检查。它不会执行被审查的代码。”

指向四个统计数字：6 个文件、12 个函数、6 条已解析调用、5 个候选问题。

## 1:15–2:00｜从目录到调用

在“仓库概览”展示目录，切换“源码阅读”选 service.py，再切到“调用关系”。

“这个订单项目从 main.handle_order 进入 service.submit_order，继续调用价格计算、存储和支付查询。调用图是代码解析的结果。对外部库和动态调用，系统会标记未解析，不会凭函数名猜连线。”

必要时展开“调用证据表”，展示每条边都有位置。

## 2:00–3:05｜报告为什么有依据

切换“问题与证据”，展开 pricing.py 的动态执行候选（如果默认不是这项，点击对应条目）。

“这一条定位到 eval 调用。但发现 eval 不等于证明存在漏洞，所以报告还写明成立条件：不可信输入能否到达这里。我们同时提供代码片段、原始行号、文件哈希、潜在影响和修复建议。”

再选择一个中风险候选：关闭证书验证或静默吞异常。

“风险等级描述可能影响；置信度描述检测器对匹配的把握。两者分开，避免把所有发现都当成已经确认的安全问题。”

## 3:05–3:50｜问答与 Agent

切到“代码问答”，点击“有哪些高风险问题？”；展开一条源码引用。

“当前展示的是本地证据问答，无需模型。配置模型后，智能体可以选择检索代码、读取源码、查询调用关系三个工具，循环获取证据后回答。引用必须来自实际读过的代码行，否则答案会被拦截。”

**不要在未配置 API Key 时声称模型已经连接，也不要说本地问答是大模型推理。**

## 3:50–4:30｜可交付与可追溯

点击“下载 Markdown 报告”。展示报告中的行号和建议。

“分析结果也能导出 JSON，包含源码快照。历史记录保存在本地数据库，刷新或重启之后能继续查看对应报告与对话。”

可以刷新网页，从左栏加载上次快照。说明历史记录是旧快照，需要查看最新代码时应重新扫描。

## 4:30–5:00｜实现与边界

“技术上，Streamlit 负责界面，Python AST 提取结构和规则候选，SQLite 保存历史，可配置模型负责补充上下文分析。我们用已知问题样例、正常代码对照和引用校验测试验证结果。”

“首版的边界也很清楚：它不运行目标代码，不保证发现所有缺陷；后续可以扩展更多语言、跨过程数据流分析和真实项目评测。”

## 常见追问

**为什么不把整个仓库直接发给模型？**  
先建立索引、按需读取，使回答能定位到明确代码片段，也更容易控制上下文和费用。

**这是不是只做了几个字符串匹配？**  
规则建立在 AST 上，会区分导入、参数遮蔽、安全参数和代码结构；调用关系也来自静态绑定解析。复杂业务缺陷仍需要更深入的分析。

**没有模型还能叫智能体吗？**  
展示版同时提供确定性的本地分析工作流和可选的模型工具调用智能体。两种模式在界面上明确区分。没有 Key 时只展示已实现的本地能力。

**如何减少误报？**  
保守解析、保留触发条件、分开风险与置信度、校验引用，并用正常对照测试；不能保证零误报。

**能否接通义千问？**  
可以通过兼容工具调用的 Chat Completions 接口配置 base URL、模型和 Key。当前交付验证包含模拟接口测试，实际账号联调需有效凭据。

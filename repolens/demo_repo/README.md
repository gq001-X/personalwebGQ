# Papertrail Orders · 订单服务审查样例

这是 RepoLens 的静态分析演示仓库，**有意保留 5 项可疑实现，仅用于读取与审查，不要运行**。它不是可部署的订单系统，也不需要安装 `requests` 等依赖。RepoLens 只解析源码，不会导入或执行这些文件。

## 业务结构

```text
main.py       接收订单请求，调用订单服务
  service.py  汇总价格、恢复缓存、记录订单
    pricing.py       价格与折扣计算
    storage.py       本地订单状态与缓存解码
    integrations.py  发票预览与支付状态查询
```

## 演示任务

1. 找到项目入口和 `submit_order` 的调用关系。
2. 解释价格计算为什么需要检查输入来源。
3. 检查退款/支付查询中的证书校验设置。
4. 查看每项发现对应的源码行号、触发条件与修复建议。
5. 导出报告，核查证据是否对应本次扫描的文件快照。

## 预置审查点（讲解者答案）

| 文件 | 审查点 | 需要确认的条件 |
| --- | --- | --- |
| `pricing.py` | 动态求值 `eval` | 表达式是否可由不可信用户控制 |
| `storage.py` | `pickle.loads` 反序列化 | 缓存字节是否可能来自不可信来源 |
| `integrations.py` | `subprocess.run(..., shell=True)` | 命令字符串是否混入未验证输入 |
| `integrations.py` | HTTPS `verify=False` | 是否会访问外部服务并处理真实敏感数据 |
| `service.py` | 广泛捕获异常后 `pass` | 失败是否会导致订单状态与外部状态不一致 |

这些是**待复核风险**。仅命中规则不等于证明已经存在可利用漏洞；报告应说明数据来源和执行条件。
